# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed
- The repository layout follows a standard structure: documentation in `docs/`, launchers in `bin/`, the manifest in `compat/`, helper scripts in `scripts/` and `scripts/e2e/`, tests in `tests/installer/`, `tests/backend/` and `tests/frontend/`. See the [README](README.md).
- All documentation, comments, messages and test names are in English.
- `scripts/make-payload.ps1` takes the worktree path as a mandatory parameter and the installer no longer contains machine specific paths.

### Added
- Community and automation files: `CONTRIBUTING.md`, `SECURITY.md`, `.github/` (CI workflow, release workflow, issue and pull request templates, `CODEOWNERS`, Dependabot), `.editorconfig`, `.gitattributes`, and architecture decision records in `docs/adr/`.
- `docs/development.md` with the Docker based end to end procedure and the problems found while building the patch inside real Superset.
- End to end helpers in `scripts/e2e/`: synthetic data loader for PostgreSQL, dashboard creation through the REST API, default filter setter and `verify-backend-compare.py`, which checks 27 values returned by `/api/v1/chart/data` against direct SQL.

### Fixed
- Installer: the `upstream_sha256` hashes of `compat.json` were computed on text without line breaks and with a BOM, so `verify` never recognized an upstream file. They are now computed on the content with LF endings, and `verify` normalizes line endings, so a Git checkout with `core.autocrlf=true` is recognized.
- Installer: copied and restored files now get the current modification time. `tsc -b` compared them with `lib/*.d.ts` generated by an earlier build and skipped them, which caused TS2305 errors on `applyDashboardComparison`.
- Payload: `Select` is imported from `@superset-ui/core/components`.
- Payload: `applyDashboardComparison` is generic and keeps the form data type of each chart (it returned `Record<string, any>` and caused 31 TS2345 and TS2322 errors).
- Payload: `granularity_sqla` is emitted only when the reference column is a plain column name.
- Payload: `extraFormData` is built with an explicit cast, because Superset declares `time_compare` both as `string` and as `string[]`.
- Payload: the PeriodCompare filter applied its data mask on every render, which froze the dashboard when a comparison was active. The mask is now applied once per distinct state.
- `BigNumberPeriodOverPeriod/transformProps.ts` reads the form data returned by `applyDashboardComparison` instead of the raw form data.

## [0.1.0] - 2026-10-24

### Added
- **Native PeriodCompare filter**: dashboard filter component to select the reference period, the comparison preset (previous period, previous month, previous year, custom) and the calculation mode (actual values, difference, percentage change, ratio).
- **Date arithmetic engine (`resolveComparison.ts`)**: pure engine to compute and shift dates, with support for whole month shifts, exact day shifts, leap years and month ends.
- **Superset backend integration**: extends `superset/models/helpers.py` with one to one temporal alignment of time series, support for ISO formats with an hour part in `query_object.py`, and the feature flag `DATE_RANGE_TIMESHIFTS_ENABLED` on by default.
- **Chart integration**:
  - `plugin-chart-table`: comparison columns and metrics, side by side or as a variation.
  - `plugin-chart-echarts`: Big Number Period over Period and Timeseries (Line, Bar, Smooth Line, Step Line).
  - `plugin-chart-pivot-table`: aggregated pivot matrix with comparison columns.
- **`follow_dashboard_comparison` chart control**: option in the time controls to enable or exclude a single chart from the dashboard comparison.
- **Idempotent installation toolchain**:
  - `install.bat`, `uninstall.bat`, `verify.bat`, `dry-run.bat`.
  - Modular PowerShell engine `installer/PeriodCompare.ps1` with the libraries `Backup.ps1`, `Verify.ps1`, `Patch.ps1`, `Restore.ps1` and `BuildFrontend.ps1`.
  - Automatic project discovery: the Superset root is looked up in the calling folder, the current folder and the sibling folders and worktrees, preferring trees with custom user plugins.
  - Full protection of custom user plugins (`superset-frontend/plugins/superset-plugin-*`), with a selective merge between the `period-compare:begin/end` markers in `MainPreset.ts`.
- **Automated test suites**:
  - 17 backend pytest tests (3 in `test_period_compare_backend.py`, 14 in `test_time_shifts.py`, an extended upstream file).
  - 28 frontend tests for the temporal logic.
  - 5 contract tests for `applyDashboardComparison`.
  - Pester suite for the installer.
  - Known limits at this release: the frontend build is not covered by the tests (`-SkipBuild`).
- **Documentation**: README, architecture, installation guide, upgrade guide, migration guide and data contract.
